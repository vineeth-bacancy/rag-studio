## M6: answer models and How it works 9, 10, 12, 13 (about 3 h + 5 h)

1. **Thinking off, verified live** for qwen3.5:4b and gemma4:e4b on Ollama
   0.32.6 (`think: false`; gemma4: also check the system prompt). A model
   that cannot turn thinking off is measured once and not adopted
   (CLAUDE.md: qwen3:4b here could not).
2. **Memory first:** gemma4:e4b is about 6.6-9.5 GB. Check `free -m`
   (≥ 7 GB available), ask the user to close VS Code/Vivaldi, run with the
   watchdog (`HANDOFF.md`), and never beside the trading app's 19:15 run.
3. **Row 10** on the best retrieval setup with cached 4B scores (6d + 4B,
   no Colab needed): `./rag eval --set a b d --prompt v3 --rerank qwen3-4b
   --profile docling-structure-embeddinggemma2 --model <tag> --ladder 10`,
   plus Set E rewritten for each model. Report Pass · Refused · Wrong,
   seconds per answer, peak memory; the user decides the default answer model.
4. **How it works 9 (Prompt):** the exact messages of a recorded answer, the
   context-budget bar, why passages are numbered, v2 vs v3 vs v4 side by side.
5. **How it works 10 (Generate and cite):** how `[n]` becomes a page (code,
   not the model), a refusal demo from a recorded trap question.
6. **How it works 12 (Evaluate):** the scorecard explained on a recorded run:
   expected facts, Hit/Miss × outcome, MRR and recall@20, Set E's chain, why
   one run of 25 questions is a hint, not proof.
7. **How it works 13 (Safety):** the injection guard on the crafted PDF
   (`tests/test_guard.py`'s fixture): hidden text drawn with and without its
   text, flagged phrases, prompt v3's fence.

**Done when:** row 10 measured for both models; How it works 9, 10, 12, 13
interactive; tests green.
